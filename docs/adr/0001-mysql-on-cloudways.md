# MySQL 8.4 on Cloudways instead of Postgres

The app, its queue workers and the database run on one Cloudways server (Vultr Johannesburg, 2 GB) with MySQL 8.4, replacing the earlier plan of Postgres in Frankfurt. Cloudways was chosen for hosting, and it offers only MySQL or MariaDB. Putting the database on the same server removed the reason for Frankfurt, which was that no managed Postgres runs in Africa. That saves about 170ms per request for golfers in South Africa at the same price.

## Consequences

- **No partial unique indexes.** "One published version per Game" and "one in-progress Practice Session per golfer" use a generated column that holds the key only while the row is live (NULL otherwise), with a unique index on it. Unique indexes allow repeated NULLs, so only live rows are checked against each other.
- **Ids are generated by the app.** Laravel `HasUuids` makes UUIDv7 ids. Games and Drills keep their text ULIDs.
- **The queue runs on Redis, not the database.** Cloudways' Supervisor panel is built around `queue:work redis`. `Bus::batch` progress still lives in the database.
- **The engine can't change.** MySQL 8.4 must be picked when launching a Debian 12 server, and can't be switched afterwards. It was chosen over MariaDB 10.11 for native JSON and functional indexes.
